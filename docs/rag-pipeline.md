# RAG 链路说明

本项目的后端把 `rag_mark/main.ipynb` 中的实验代码整理为可测试、可持久化的服务。

## 1. 文档接入

- 支持 UTF-8、UTF-8 BOM 和 GB18030，兼容 `rag_mark` 中读取的 GB18030 小说文本。
- 当前接受 `.txt`、`.md`、`.markdown`。
- 原始文件保存在 `data/books/{book_id}/`，索引保存在 `data/chroma/`。

## 2. 切块

默认 `chunk_size=300`、`chunk_overlap=50`。切块优先寻找句号、问号、感叹号、分号和换行；只有找不到合适的语义边界时才按固定长度截断。片段同时保存字符起止位置，便于以后做原文定位。

## 3. 向量召回

使用 `text2vec-base-chinese` 生成归一化向量，并写入 Chroma 的 cosine 空间。查询时先用问题向量召回 `RETRIEVAL_CANDIDATES` 个候选片段。Chroma 使用持久化客户端，因此服务重启后书库仍然存在。

## 4. 重排

召回候选会送入 `mmarco-mMiniLMv2-L12-H384-v1` CrossEncoder，对“问题 + 原文片段”逐对打分，再截取最终 `top_k`。重排模型不可用时，服务记录警告并退回向量召回顺序，不影响书库和基础问答。

## 5. 生成与引用

最终片段带编号加入提示词，模型只能基于原文回答，并使用 `[1]`、`[2]` 标注依据。API 同时返回结构化 `evidence`，前端可以自行渲染原文引用，而不依赖模型生成的引用文本。

前端通过 `POST /api/v1/questions/stream` 消费 SSE：

1. `meta` 先返回检索证据，证据面板立即更新。
2. `delta` 随 Gemini 生成持续返回文本，前端逐段追加。
3. `done` 标记生成完成，并返回最终模式和模型。
4. 模型在输出前失败时，服务端继续用 `delta` 推送检索摘录，保持同一 SSE 协议。

未设置 `GEMINI_API_KEY`，或生成接口临时失败时，服务返回 `extractive` 模式，直接展示最相关的原文片段。

## 6. 当前边界

- 只支持纯文本和 Markdown，PDF/EPUB 需要后续增加解析器。
- 非流式 JSON 接口继续保留，供脚本和兼容客户端使用。
- 书库元数据当前从 Chroma 片段元数据聚合，适合个人书库；大规模多租户场景应拆出独立元数据数据库。
